# Sun 插件开发手册

本文档说明如何为 Sunday 桌宠编写插件模块。所有插件即 `mudels/` 目录下的一个 `.py` 文件。

## 一、核心机制

- `sun` 命令启动时，`sun_cli.py` 会扫描 `mudels/*.py`，把每个文件**自动加载并实例化**。
- 模块类的构造函数接收一个参数 `G`（全局对象），必须保存为 `self.g`。
- `g` 上挂载了所有模块的实例，例如 `self.g.log`、`self.g.config`、`self.g.mgmg`。**所有模块共享同一个 `g`**，因此不存在数据不同步问题。
- 模块不需要手动注册，文件名（或 `name` 属性）就是它的命令名。

```python
# mudels/hello.py
class Hello:
    def __init__(self, G):
        self.g = G
        self.name = "hello"
```

## 二、标准属性

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `self.g` | 全局对象 | 必须保存构造函数传入的 `G`，用于模块间通信 |
| `self.name` | str 或 list | 模块名；为列表时第一个是展示名，其余是别名。如 `["cmd", "list"]` 使 `sun list` 也能命中 |
| `self.run_methods` | list | 可通过 CLI 调用的子命令方法名列表，如 `["run", "stop"]` |
| `self.call_is_runnig` | bool | call() 是否已运行（防重复初始化） |

## 三、两个入口方法

### `call()` — 启动时自动调用一次

用于初始化、常驻服务、注入组件。按依赖顺序调用：`log → config → cmd → mgmg → lobo → 其余按文件名`。

```python
def call(self):
    if self.call_is_runnig:
        return
    # 初始化逻辑...
    self.call_is_runnig = True
```

### `run(name)` — 运行时动态调用

注册到 CLI：`sun <模块> <参数...>` 会调用 `run(参数)`。

```python
def run(self, name: str = ""):
    print(f"hello {name}")
```

### 子命令 `run_methods`

模块声明 `self.run_methods = ["run", "stop"]` 后，`sun mgmg stop` 会直接调用 `stop()` 方法（不再走 `run`）。

## 四、模块间通信（self.g）

所有模块共享同一个 `g` 对象，通过 `self.g.<模块名>` 访问：

```python
def call(self):
    # 写日志
    self.g.log.run("我的模块启动成功")
    # 读写配置
    api_key = self.g.config.get("api_key", "")
    self.g.config.set("theme", "dark")
    # 弹气泡提示
    self.g.mgmg.dm_print("你好呀", 3000)
```

常用接口速查：

| 模块 | 接口 |
| --- | --- |
| `log` | `self.g.log.run(text)` 写日志 |
| `config` | `self.g.config.get(key, default)` / `set(key, value)` / `save()` |
| `mgmg` | `dm_print(text, ms)` 气泡 / `t_print(text)` 快捷气泡 / `is_widget_alive(w)` |
| `clipboard` | `self.g.clipboard.get_text()` / `set_text(text)` / `add(text)` |
| `cmd` | `self.g.cmd.record(module, method)` 手动上报调用统计 |

## 五、重载覆盖其它模块的方法

插件可以替换其他模块（含 `mgmg`）的方法，实现"打补丁"。参考 `lobo.py` 的 `_mount_clipboard`：

```python
def call(self):
    cb = self.g.clipboard
    if cb is None or self._mounted:
        return
    orig_tool = cb.tool              # 保存原方法

    def patched_tool():
        orig_tool()                  # 先执行原逻辑(读剪贴板并生成"〇"按钮)
        # 再追加自己的逻辑(把剪贴板内容发到手机)
        self.send_text(self.g.clipboard.get_text())

    cb.tool = patched_tool           # 用包装函数替换
```

注意：重载发生在 `call()` 阶段，此时被覆盖的模块已初始化完成（如 `mgmg.root` 可用）。

## 六、无类模块（函数模块）

如果文件里没有类，整个模块会被直接挂到 `g` 上（如 `emo.py`）。函数通过参数接收 `g` 和 `mgmg`：

```python
def load_emo(g):
    g.data_emo_path_list = []

def emo(g, mgmg, number=1):
    ...
```

这种模块不会被 `sun list` 列出（没有 `run` / `run_methods`）。

## 七、调用统计与 sun list

- `sun_cli` 在每次分发（run / 子命令）时自动调用 `self.g.cmd.record(模块名, 方法名)`。
- `sun list` 会按累计调用次数降序列出所有模块及其子命令，用得多排前面（列表不显示次数）。
- 统计随配置一起持久化在 `data/config/config.json` 的 `cmd_usage` 键中。
- 插件内主动触发的调用可手动上报：`self.g.cmd.record("mgmg", "run")`。

## 八、注意事项

1. **不要直接 import 模块全局变量**：模块间一律通过 `self.g.xxx` 通信，否则脱离框架无法运行、难以测试。
2. **GUI 环境判断**：不是每次 `sun` 都会创建 GUI（如 `sun list`）。需要 GUI 时先判断 `self.g.mgmg.root` 是否存在。
3. **回调线程安全**：tkinter 只能在主线程操作界面，耗时任务开 `threading.Thread`，完成后用 `mgmg.root.after(0, 回调)` 回到主线程。
4. **Linux 兼容**：Windows 专有 API（如 `wm_attributes('-transparentcolor')`）在 Linux 会抛异常，务必 `try/except` 包裹。
5. **日志**：用 `self.g.log.run(...)` 而不是 `print`，便于统一排查。
